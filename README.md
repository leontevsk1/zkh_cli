# ZKH_CLI: Voice-to-Data Pipeline for Housing Services

**zkh_cli** — это прототип системы автоматизации диспетчерской службы ЖКХ. Проект переводит голосовые обращения жителей в структурированные заявки, определяя тип проблемы, уровень срочности и формируя краткую выжимку (summary).

## 🏗 Архитектура системы

Проект разделен на три независимых вычислительных блока:

1. **Whisper (ASR):** Распознавание речи через `faster-whisper`.
2. **ML Engine (NLU):**
* **Service Classifier:** Логистическая регрессия + Rule-based фичи для определения типа службы.
* **Urgency Regressor:** LightGBM для оценки приоритета (1–4).
* **Summarizer:** Модель RuT5-small (с поддержкой LoRA-адаптеров) для суммаризации.


3. **UI/Storage:** CLI-интерфейс для подтверждения оператором и логгирование в JSONL.

## Установка и развертывание

Для удобства развертывания подготовлен скрипт `install.py`, который автоматизирует рутину:

```bash
python install.py

```

**Что делает скрипт:**

* Клонирует репозиторий.
* Создает изолированное виртуальное окружение (`.venv`).
* Устанавливает зависимости из `req.text` (включая `torch`, `transformers` и `lightgbm`).
* Скачивает и распаковывает предобученные веса моделей из GitHub Releases.

## 🚀 Использование (CLI)

Основная точка входа — `src/main.py`.

```bash
# Активация окружения
source zkh_cli/.venv/bin/activate

# Запуск обработки аудиофайла
python src/main.py --audio path/to/voice_message.wav

```

### Доступные флаги:

* `--audio`: Путь к файлу (wav, mp3, m4a и др.).
* `--config`: Путь к `config.json` (по умолчанию используется встроенный).
* `--yes`: Автоматическое подтверждение и сохранение без участия оператора.

##  Подробности ML-блока

### Гибридная классификация (`service_clf`)

Вместо чистого глубокого обучения используется **Feature Union**:

* **TF-IDF:** Векторизация текста для поиска семантических связей.
* **RuleFeatures:** Модуль на основе регулярных выражений (лексиконы для ГВС, лифтов, отопления и др.), что гарантирует точность на специфическом профессиональном сленге.

### Оценка срочности (`urgency_lgbm`)

Используется `LGBMRegressor`, который принимает на вход не только текст обращения, но и уже предсказанную категорию службы, что позволяет модели учитывать контекст (например, «залив» в «ГВС» критичнее, чем «грязный подъезд» в «Управлении домом»).

##  Структура данных (JSONL)

Результат каждой подтвержденной заявки сохраняется в `zkh-pipeline/messages.jsonl` в формате:

```json
{
  "ts": 1709823600,
  "ml": {
    "service": "Электроэнергия",
    "service_prob": 0.98,
    "urgency": 1,
    "summary": "Нет света в первом подъезде, искрит щиток."
  }
}

```
